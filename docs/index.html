How a request moves

The host authenticates the project context before a plugin can run. A plugin never chooses its own authorization boundary.

Client → host transport → project context → permission broker → plugin worker
                                           ↓
                                  lifecycle + grants + audit
                                           ↓
                                  scoped response / commit

Current backend focus

  • Project-scoped plugin installation and authorization
  • Manifest-driven routes, capabilities, and imports
  • Worker supervision and external worker handshakes
  • Lifecycle preview, drain, stop, recover, remove, and uninstall
  • Race-tested permission and lifecycle transitions

Local rules

Do not run Docker during ordinary development. Use in-process tests and SQLite for fast local checks. PostgreSQL/Compose checks remain explicit integration or release checks.
