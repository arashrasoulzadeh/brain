Developer guide

Make one small, verified change at a time.

Every backend change follows failing test → smallest implementation → focused verification → commit and push.

Quickstart

# no Docker required for ordinary local work
GOCACHE=/tmp/brain-go-cache go test ./...
go vet ./...
npm run lint:ts
npm run typecheck
npm run test:ts

Use Docker or Compose only for an explicit PostgreSQL/release integration check. Document the command before running it.

Plugin shape

Required boundary

plugins/<plugin-id>/
  index.ts
  plugin.yaml

Manifest owns policy

Declare title, description, version, routes, functions, capabilities, source files, imports, and plugin dependencies in plugin.yaml. The host rejects undeclared operations and imports.

Minimal plugin example

# plugins/notes/plugin.yaml
id: notes
version: 1.0.0
host_api: 1
entrypoint: index.ts
source_files:
  - index.ts
imports:
  - ../sdk-typescript/src/index.js
capabilities:
  - notes.read
routes:
  - operation: notes.list
    function: listNotes
    capability: notes.read
// plugins/notes/index.ts
import { createHostHandler } from "../sdk-typescript/src/index.js";

export const listNotes = createHostHandler("notes.list");

Execution flow

1. Load and validate plugin.yaml
2. Verify source_files, imports, and dependencies
3. Register version and readiness state
4. Install for a project and grant declared capabilities
5. Host authenticates project context and issues scoped invocation
6. Worker executes the declared route
7. Commit rechecks lifecycle, grant, version, and single-use credential

Contribution checklist

  1. Read AGENTS.md and the active phase guide.
  2. Decompose affected plugin code before adding behavior.
  3. Write one focused failing test under tests/.
  4. Implement the smallest passing change.
  5. Run focused, package, race, lint, and full checks.
  6. Update the roadmap checkbox only after verification.
  7. Update developer/admin docs and newest-first changelog.
  8. Commit one focused checkbox and push it.
